# プリプロ名人Codexへの修正指示書：おはなし名人の音楽・SE対応

2026-10-25 JST。受け取り側でこの文書をそのまま作業指示として使ってください。
今回のおはなし名人側作業では、プリプロ名人のコードは変更していません。

## 目的と現在の互換性

おはなし名人の段落種別にmusic／seを追加しました。音楽・SEは発話と別で、画面の「音響」から指定できます。

**保存形式のトップレベルはversion:2のままです。既存のformats配列には新しい列挙値を入れていません。** 音響行は従来どおりactionとして保存し、本文に「音楽：」「SE：」を残します。これに加えて章内の任意項目soundCuesを追加しました。

調査したプリプロmainは `5aec90d751604890a487443d15243ff33e0b720c`。`js/scriptbridge.js` の保存v2受信器は既に音楽：／SE：の接頭辞を読めるので、今回のJSONは現行コードでも読み取れます。既存UIにもmusic／seがあります。直ちに受信不能になる破壊的変更はありません。

共通交換仕様案 `meijin.script-exchange / 0.1-draft.1` は別形式です。今回、そのスキーマや版、kind列挙値を変更していません。未合意の共通仕様を正式化したものではありません。現行仕様案ではaction.raw内の接頭辞で受け渡せます。

## 1. JSONの追加項目と具体例

```json
{
  "version": 2,
  "title": "音響の試験",
  "chapters": [
    {
      "id": "chapter-001",
      "title": "日常",
      "text": "#C1\n◯自宅（朝）\n音楽：静かな曲\nSE：足音\n人「こんにちは」",
      "cuts": [{"id": "cut-001", "line": 0}],
      "formats": [null, "scene", "action", "action", "dialogue"],
      "formatOrigins": [null, "manual", "manual", "manual", "manual"],
      "soundCues": {
        "version": 1,
        "entries": [
          {"line": 2, "kind": "music", "raw": "音楽：静かな曲"},
          {"line": 3, "kind": "se", "raw": "SE：足音"}
        ]
      }
    }
  ]
}
```

- soundCuesは任意。ない旧ファイルも受け入れてください。
- soundCues.versionはこの追加情報の版で、作品の保存v2や交換案の版とは別です。
- entries[].lineは章textをLFで分割した0始まりの物理行位置。カット番号行も含みます。**永続IDとして使用しません。** 編集・空行整理・カット分割で再計算します。
- kindはmusic／se。rawは同じ行の元文字列そのままです。空白や全角の文字を勝手に正規化しないでください。
- rawは古い編集ソフトによって行位置が変わった場合の検証用です。位置だけを信頼せず、該当行との完全一致、音響接頭辞、発話の引用内ではないことを確認します。
- 音響行のformatsはactionを維持。scene／dialogue／nullの既存意味は変更しません。柱と音響はカット境界ではなく、絵やカットを増やしません。
- サンプルは `docs/interop/samples/sound-v2.json`、追加情報のSchemaは `docs/interop/sound-cues.schema.json`。

## 2. プリプロ側で行う読み込み・表示処理

以下は既存の読み込みアダプターに対する小さい拡張として行ってください。おはなしの内部DOMやUIに依存させないでください。

1. まず既存の保存v2受信を維持します。formatsにmusic／seを許す変更は不要です。章のsoundCuesがない場合も現在の接頭辞解析で受信します。
2. soundCues.version===1なら、entriesの型・重複・範囲・raw一致・kindと接頭辞の一致を検査します。カット見出し行への指定、発話のカギ括弧内、raw不一致を無条件には採用しないでください。不一致は警告し、現在の本文解析へ戻します。
3. 未知のsoundCues版は、追加情報を無理に解釈せず、接頭辞解析と警告で扱ってください。元JSONは保持します。既存の共通交換案の未知版拒否ルールとは分けてください。
4. 有効な音響指定を、既存の脚本行kind:music／seへ対応させます。who／speakerIdはnullとし、先頭の音楽：／SE：は本文表示で二重にしないでください。descriptionは接頭辞の後の内容です。発話の音声尺・話者として扱わないでください。
5. 現在の脚本管理画面の音楽・SE種別を再利用します。新しい独自種別や常時ボタンを重複追加しないでください。表示種別を変更するときは既存の編集履歴・一括編集に参加させます。
6. 外部カットIDとの対応、差分プレビュー、手動確認、Undo／Redoを維持します。音響行の物理行位置や表示カット番号で既存素材を紐付けないでください。新しい音響指示だけで音声ファイル、画像、尺、カメラ情報を作成・上書き・削除しないでください。
7. 保存v2受信とdraft.1のアダプターを分離してください。draft.1のaction.rawも既存の音響接頭辞で解釈できます。正式な独立music／seブロックを外部交換仕様に足す場合は、既存draft.1を変更せず、別版として両アプリで合意する作業に分けてください。

現在のmainが既に同等の検査・表示を持っている場合は再実装せず、不足した部分とテストだけ追加してください。

## 3. 既存データとの互換性

- `音楽「曲名」`、`SE「音」` のような旧来のセリフ風表記は、おはなし側で自動的には書き換えません。利用者が音響種別へ変更すると `音楽：曲名`、`SE：音` に変換し、Undoで戻せます。曖昧な既存表記を無断で音響に変更しないでください。
- 発話内の改行で `SE：これは発話の続き」` が現れるケースは、音響の新規行ではありません。括弧の状態を保持してください。
- 古いおはなし版が追加情報を無視・保持したまま行を変更しても、現在の本文接頭辞とraw照合から再構築できます。古いsoundCuesだけで本文を上書きしないでください。
- おはなし側は未知のsoundCues版を読み込む際には原稿を保護して停止します。追加情報を破棄して自動保存しません。
- おはなしの推定尺では音楽・SEを台詞字数や動作1行の秒数に加算しません。実際の音響尺は未指定です。プリプロに既に設定された音声・尺を再推定して変更しないでください。
- 今回も作品・段落・音響行の永続IDを新設していません。対応が曖昧な行は利用者確認が必要です。

## 4. 両アプリ間の連携テスト

共通合成原稿を使用し、利用者の実作品や素材をテストに同梱しないでください。

- 旧保存v2（soundCuesなし）、追加情報あり、接頭辞だけのTXT、既存draft.1を受信する。
- music／se／通常台詞／OFF／ナレーション／柱／ト書きを混在させ、種別と話者を確認する。
- 音楽→SE→セリフ→ト書き、複数段落の種別変更を保存・再読込して確認する。
- 古い引用符表記を明示変換した場合と、未変換のまま保持した場合を分ける。
- 台詞内の改行・音響接頭辞風の文字列を、新しい音響や絵変わりにしない。
- 音響の本文編集、カット分割、章並び替え、空行整理後もraw・lineを照合する。重複／欠番の表示番号をIDにしない。
- 同一JSONを2回読むと増殖しない。更新差分と新規行をプレビューし、キャンセルで不変、確定後は一括Undo／Redoで元へ戻る。
- 不一致のraw、重複行指定、未知版、範囲外、矛盾するkindを安全に処理し、元データと既存素材を保護する。
- 受信前後で既存の画像・音声のバイト列、尺、カメラ・トランジション等が勝手に変わらないことを比較する。
- PCとスマホの画面で既存の音楽・SE表示を確認する。実機未確認は明記する。

おはなし側の検証はNodeモデル、ブラウザの入力／種別変更／Undo・Redo／保存、プリプロmainのreadScriptを変更せず呼ぶ契約試験です。プリプロ画面上での差分確定と実素材保護は、受け取り側で上記の試験を行ってください。
