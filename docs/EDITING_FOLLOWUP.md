# Enter確定・話者入力・形式変更（2026-10-25）

## 変更

- 2回目のEnterで入力待ちカットを直ちに表示する。以前は内部で境界を作っても実本文のないカットとして非表示にし、入力後まで見えなかった。
- 末尾の入力用段落を保存本文から除外し、分割用の空行を残さない。セリフ末尾の閉じ括弧直前で2回Enterを押す場合も、閉じ括弧を元のセリフへ戻して区切る。IME変換確定のEnterは分割に使わない。意図的な本文間の空行を一律に削除しない。
- 「話者」ボタンで専用の入力欄を開き、セリフの話者名を設定・変更できる。従来の空セリフは「」の内側にカーソルを置くため、名前を入れる操作がわかりにくかった。新しい入力欄は変換中に本文を再描画せず、確定直後のEnterによる誤送信も防ぐ。折返し行からも元のセリフを対象にする。
- セリフから別形式へ変更した場合は外側の「」を除き、内側の引用符・話者名・本文の文字は残す。柱から別形式へ変更した場合は先頭の○／◯／〇だけを除く。本文中の通常の〇や引用符を一括置換しない。削除した記号分だけカーソル位置も補正する。変更はUndo／Redoに参加する。

## 保存・連携

保存v2を維持し、章の任意項目pendingCutIdに、末尾の入力待ちカットのIDを保存する。textはカット番号で終わり、不要な空白本文を追加しない。cutsにはその永続IDと行位置が入り、入力開始後は同じIDを実カットとして使ってpendingCutIdを解除する。

本文のない入力待ちはPDF・印刷の実カットに含めない。旧版が入力待ちカットを整理してフラグだけ残した場合は、現在版で古いフラグを無効化して本文を開き直す。空カットを勝手に復活させない。旧版はこの新しい入力待ち状態の保持に対応しないが、本文は従来の保存v2として扱える。

現行プリプロの受信器でJSONを実際に読み、予約IDが維持されることを確認した。読み込み側では空の入力待ちをプレビューし、未入力のカットから素材を自動作成しない。プリプロ側のコードは変更していない。共通交換仕様案draft.1の版やkindは変更しない。

## 検証

専用62項目：PC／スマホ相当、縦書き／横書き、2回Enter直後の表示、入力前の保存・再読込、Undo／RedoとID維持、セリフ内からの分割、話者欄のChromeネイティブcomposition、形式記号の除去、引用保持、カーソル位置。

既存54、IME110、音楽・集中70、書式36、レイアウト115、前段の使用後修正66、PWA15、Nodeとプリプロ受信契約も合格。既存書式試験の期待値は今回指示された記号除去に合わせて変更した。
