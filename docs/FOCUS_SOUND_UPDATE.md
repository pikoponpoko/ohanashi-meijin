# 集中モード・音楽／SE（2026-10-25）

利用者の追加指示により、⑦を仕様案から実装へ進めた。前回の使用後10項目も同じPR #10で維持する。プリプロ側は読み取りのみで変更しない。

## 表示と操作

- 集中モードの上下の帯と本文背景を同じpaper色にする。明暗テーマとも背景色を統一し、本文のサイズ・行間・内部余白は維持。
- 集中モード開始操作から直接ブラウザ全画面を要求する。別の「全画面」ボタンは削除。全画面非対応／拒否時は画面内の集中表示を利用し、常に終了できる。終了はアクセシブルな名称を持つ×。ブラウザ仕様により、ページを開いただけで無操作の全画面開始はしない。
- 上右の章番号／章名を廃止し、章名だけを下中央へ配置。左右の章移動とショートカットは維持する。
- スクロールバーは操作時の色を18%の不透明度へ抑える。操作領域を維持し、高コントラストではネイティブ色を使う。
- 自動修正のバッジは実際に修正できる指摘と空行整理だけを数える。助言だけの指摘2件が「自動修正・2」になる不一致を解消した。
- カット番号の追加余白は**手前側**。縦書きは番号列の右側、横書きは上側。以前増やした後ろ側の余白は元へ戻す。保存文字列とカットIDを変更しない。

## 音楽・SE

既存の書式ボタンの横の「音響」選択から、music／seを独立した入力種別として指定する。ボタンを多数増やさず、音楽・SEの接頭辞と既存テーマ内の控えめな表示色で区別する。

単段落・複数段落、空の入力枠、縦書き・横書き、別の種別への変更、コピー／貼付、Undo／Redo、保存・再読込、PDF・印刷に対応した。旧式の音楽「…」／SE「…」は自動で書き換えず、利用者が種別を選んだ場合に変換する。音響内の引用符を発話の開始として扱わず、発話の引用内に現れるSE：は音響にしない。

保存v2のformatsは既存の3種を維持し、音響行を互換用actionとして保存。任意のsoundCues.version=1にline／kind／rawを追加する。本文にも音楽：／SE：を残し、現行のプリプロ受信器で読める。旧編集による行位置ずれはrawを検証し、本文から再構築する。初回のブラウザ保存移行時は元JSONを-before-sound-cuesにも保持する。未知版の音響情報は原稿を保護して停止する。

音楽・SEは台詞字数や動作時間の推定に加算しない。音響尺は未指定のため、実際の尺を予測した値ではない。共通交換仕様draft.1そのものは変更していない。

## 引き渡し・検証

[プリプロ名人Codexへの修正指示書](PREPRO_SOUND_HANDOFF.md)に、JSON例、受信処理、表示、互換性と両側のテスト項目を記載した。現行プリプロmain 5aec90dのreadScriptを実際に呼び、新しい音響情報あり／なしのJSONが同じmusic／seと話者nullで読めることを確認した。既存素材へ自動同期していない。

実OSの日本語IME候補画面、iPhone／Android実機、Safariの全画面とOSファイル許可、プリプロ画面での手動差分確定は未確認。Chromeの実際のFullscreen API、タッチ相当の画面、拒否時のフォールバック、保存、履歴は自動確認した。画像は [screenshots/focus-sound](screenshots/focus-sound)、ログは [test-results/focus-sound](test-results/focus-sound)。公開結果はPR #10を参照する。

確認済み：専用70項目、既存54／追加82、入力・composition110、書式36、集中操作28、前段の使用後修正66、レイアウト115、公開後受入59、TXT34、PWA15、Node。現在のプリプロ受信器との契約試験と、前のmainモデルによる新JSON読み込み・古い編集後の位置再構築も合格。音楽・SEに関するJSON例は渡す指示書に記載している。
