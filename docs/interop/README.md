## 維持する対応

| 内部／保存v2 | 現行の受信 | 交換仕様案 |
|---|---|---|
| 章id・title・配列順 | chapterIdと章順 | chapters[].id/title/cuts |
| cuts[].id | 外部カットIDとして保持 | cuts[].id。表示番号をIDにしない |
| cuts[].line／#C番号 | 境界位置／表示番号 | 配列順／displayNumber。内部の行番号を外部キーにしない |

| formats:dialogue、カギ括弧 | 話者、OFF、ナレーション、括弧内の折返し | dialogue、speaker、delivery。1台詞内の改行を絵変わりにしない |
| 「音楽：」「SE：」＋action | music/seとして現行パーサーが読める | 原案には独立music/seブロックがない。正式な拡張は未合意 |

## 安定化の境界（設計方針、送信機能は未実装）

内部の段落DOM・書式表示・行位置は送信アダプターの入力に限定する。外部形式は固定した版の検証器とシリアライザーで生成し、内部のフィールドをそのまま全量公開しない。共通形式が不変なら、内部UIの変更はおはなし側アダプターと契約試験だけで吸収する。

既存draft.1のプロパティ名、作品IDの生成／複製／復元、revisionの分岐、段落・シーン・話者IDは未確定。独断で正式化しない。意味や必須項目の変更は新しい版を提案し、旧版の読み取りを残す。未知版は確認なしに取り込まない。受信差分は永続IDで対応させ、追加・削除候補・移動・本文変更をプレビューし、手動確認とUndoを必須とする。既存素材・尺は消さない。

## ⑦ 音楽・SEの仕様提案（未実装）

ボタンを常時2個増やすより、既存のト書き操作に小さい入力種別選択を設ける案を推奨する。音楽・SEは発話ではなく音響指示として表示し、本文の文字サイズ・行間は維持する。

1. 互換優先の第1案：保存v2ではactionと明示的な「音楽：」「SE：」を用いる。受信側の既存パーサーで区別できる。見かけ上の独立操作であり、正式な独立JSON種別追加とは分ける。引用符付きの `SE「…」` 等は自動変換せず、確認を経て変更する。
2. 将来の完全な独立種別案：内部roleと外部music/seブロックを定義する。現在の保存v2とdraft.1の許可種別には追加できないため、版付き移行と両側の受信対応が必要。プリプロ側にも変更が必要になるので、今回は実装しない。新しいUI機能のたびに仕様を変えず、音響の意味を合意してから版を固定する。

今回、音楽・SEボタン、種別、自動変換、共通JSON送信は追加していない。

## 共通試験

[共通保存v2原稿](samples/native-v2.json)、[旧交換案](samples/baseline.json)を `tests/interop.cjs` に渡し、プリプロ最新mainの `readScript` を実際に呼んだ。原本は使用せず合成原稿だけ。

`PREPRO_REFERENCE=/tmp/prepro-usage-reference node tests/interop.cjs`

参照先はmainの読み取り用スナップショット（ES modules）とする。プリプロの作業ツリーを編集・実行時修正しない。

確認済み：保存v2のID・章順、空行整理後のID維持、構造的な柱、音楽・SEの明示接頭辞、1台詞内の改行、動作行、入力オブジェクト不変。draft.1は通常読み込みで拒否し、明示試験時のみ受理する。プリプロの画面での手動差分確定と既存素材保護の結合操作は今回未確認。正式仕様合意・本番送受信完了とは報告しない。
